## Checkpoint distribution

Large checkpoints are not bundled into the GitHub source repository or duplicated as GitHub Release attachments. They are distributed through the Hugging Face `shute2004/virtual-fly` project overview.

The publication structure separates:

- `virtual-fly-initial-YYYYMMDD` — canonical v1 initial checkpoint;
- `virtual-fly-trained-YYYYMMDD` — canonical v1 post-training checkpoint;
- `virtual-fly-video-before` — historical checkpoint used for the published video's Before side;
- `virtual-fly-video-after` — historical checkpoint used for the published video's After side.

The canonical date suffix is chosen only on the actual publication day. The historical video pair is not the canonical initial/trained pair. Internal historical versions are retained only in provenance/model cards.

Exact checkpoint hashes, attribution, and model-card templates are tracked in `release/huggingface/`.

## Historical visualization assets

If attached to this release, the `historical-before-after-v240-v966*` assets are explicitly **historical development media**, not canonical evidence.

They visualize a v240 → v966 lineage in which the recorded before state passed one gate and the after state passed two under the recorded historical evaluation condition. That lineage has provenance/semantic differences from canonical v1.

Exact asset hashes and roles are in [`release-assets-v0.1.0.json`](release-assets-v0.1.0.json).
