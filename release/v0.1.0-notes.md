# virtual-fly v0.1.0

First research-OSS publication milestone for `virtual-fly`.

## What this release contains

- the current Rust whole-MaleCNS neural runtime and Python embodiment/orchestration stack;
- the production closed-loop Flyppy path using local direct-ray visual input, MaleCNS neural dynamics, local synaptic plasticity, individual motor-neuron output, and FlyBody/MuJoCo physics;
- canonical experiment v1 config, provenance manifest, compact result, and end-to-end reproducer;
- matched English, Japanese, and Simplified Chinese public research documentation;
- citation, licensing, third-party attribution, and optional future archival metadata.

## Canonical v1

The recorded canonical experiment was actually run from clean commit `7fa464aad7269d34f46f1171080b51e095d1d811`. A pre-publication privacy-only history rewrite produced the content-equivalent public scientific commit:

```text
f9c86c904d67ff974f3c43d37aab3619bc93fc1b
```

At the canonical point, the rewrite changes only the local OS username in 14 historical report/provenance files. Executable source, canonical conditions, and scientific artifact-generation logic are unchanged.

Canonical v1 uses a fresh MaleCNS v1.0 source/snapshot, current class-DAN semantics, body v7 / environment v7, direct-ray K13 vision, the 97-neuron haltere timing subset, population 2 asynchronous shared weights, boundary-band curriculum, and six training episodes.

Observed result:

- global weight version v0 → v6;
- aggregate neural step 484;
- exactly 2,163,179 / 25,582,938 stored edges changed;
- frozen initial state: one gate, then gate collision at control step 120;
- frozen final state: one gate, then gate collision at control step 120.

The frozen comparison disables both plasticity and task-triggered DAN current.

**The short canonical run did not show categorical behavioral improvement.** It demonstrates a traceable current-code execution chain and local-plasticity-driven stored-weight changes; it does not establish generalization or long-term learning stability.

## Checkpoint distribution

Checkpoint payloads are not bundled into the GitHub source repository or duplicated as GitHub Release attachments. They are distributed through the Hugging Face `shute2004/virtual-fly` overview and four hash-verified checkpoint repositories.

The publication structure separates:

- [`virtual-fly-initial-20260920`](https://huggingface.co/shute2004/virtual-fly-initial-20260920) — canonical v1 initial checkpoint;
- [`virtual-fly-trained-20260920`](https://huggingface.co/shute2004/virtual-fly-trained-20260920) — canonical v1 post-training checkpoint;

- [`virtual-fly-video-after`](https://huggingface.co/shute2004/virtual-fly-video-after) — historical checkpoint used for the published video's After side.

The canonical repository date is 2026-09-20. The historical video pair is not the canonical initial/trained pair. Internal historical versions are retained only in provenance/model cards.

Exact checkpoint hashes, attribution, and model-card templates are tracked in `release/huggingface/`.

## Historical visualization assets

If attached to this release, the `historical-before-after-v240-v966*` assets are explicitly **historical development media**, not canonical evidence.

They visualize a v240 → v966 lineage in which the recorded before state passed one gate and the after state passed two under the recorded historical evaluation condition. The Before state was **not untrained**: v240 had already undergone 240 historical training episodes. Playback disabled plasticity but retained task-triggered PAM stimulation, the comparison was not held out, and v966 belongs to a mixed older lineage. These conditions differ materially from canonical v1 frozen evaluation, where both plasticity and task-triggered DAN stimulation are off.

The X-post video, README-GIF source video, and GitHub Release MP4 are separate renderings of this same historical comparison and have separate hashes. Exact asset hashes and roles are in [`release-assets-v0.1.0.json`](release-assets-v0.1.0.json). The standalone Release assets also include `THIRD_PARTY_NOTICES.md`, which carries the relevant upstream licensing and attribution notice for the historical media.
