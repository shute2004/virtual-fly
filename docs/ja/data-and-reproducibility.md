# データの来歴と再現性

[English](../en/data-and-reproducibility.md) · [日本語](data-and-reproducibility.md) · [简体中文](../zh-CN/data-and-reproducibility.md)

## 1. 基準データ

初期基準には、HHMI Janeliaなどが公開している成体オスショウジョウバエ全CNSコネクトーム`male-cns:v1.0`を使う。

公式配布ではneuPrint APIと一括ダウンロードの両方が提供されている。データセット本体のライセンスはCC-BYである。

データ取得時には、少なくとも次を記録する。

- データセット名
- データセットの版
- 取得元URL
- 取得日
- 上流データのライセンス
- 上流データの引用情報
- 各ファイルのハッシュ値
- 変換ツールの版
- 変換時の設定

## 2. 生データを直接編集しない

外部データは、読み取り専用の元スナップショットとして扱う。

```text
上流の元データ
      ↓
検証済みのローカルスナップショット
      ↓
内部形式へ正規化した静的データ
      ↓
仮想個体ごとの可変状態
```

学習や可塑性による変更を、元のコネクトームへ書き戻してはいけない。

## 3. データの層

### 層A: 上流データ

取得した原データ、または公式APIから得た応答。

### 層B: 正規化済み静的データ

内部形式へ変換した、読み取り専用のデータ。

例:

- ニューロン一覧
- シナプスや集約接続
- 注釈
- 形態情報への参照
- 来歴情報

### 層C: 仮想個体の状態

仮想個体ごとに変化し得る状態。

- 神経状態
- シナプスの機能状態
- 構造変化の差分
- 神経修飾状態
- 身体状態
- 実験履歴

## 4. 来歴の区分

値、パラメータ、接続には可能な限り次の区分を付ける。

| 区分 | 意味 |
|---|---|
| `observed` | 実測されたもの、または上流データに直接存在するもの |
| `literature` | 文献から採用したもの |
| `inferred` | 実測情報から推定したもの |
| `assumed` | 未知部分を埋めるために仮定したもの |
| `calibrated` | 数値的・実験的に較正したもの |

論文、README、可視化では、これらを混同しない。

## 5. 実験ごとの来歴記録

各実験には、機械可読な来歴記録を生成する。

例:

```yaml
experiment_id: exp-...
fly_id: fly-...
parent_checkpoint: ...
code_commit: ...
connectome:
  dataset: male-cns:v1.0
  normalized_snapshot_hash: ...
neural_model:
  name: ...
  version: ...
plasticity_model:
  name: ...
  version: ...
body:
  model: flybody
  version: ...
environment:
  name: flyppy
  config_hash: ...
rng:
  seed: ...
```

この例にある英字は、機械可読ファイルで使うフィールド名である。説明文では、それらをそのまま日本語の文中に混ぜる必要はない。

## 6. 再現性の段階

### R0: 条件を特定できる

同じ入力データ、設定、コード版を特定できる。

### R1: 同一実行環境での決定論的再現

同じ実行方式・同じ環境なら、同じ結果を再生できる。

### R2: 実行方式をまたいだ整合

CPU / GPU / WebGPUなど異なる実行方式でも、許容誤差内で同等の結果を得られる。

### R3: 統計的再現

非決定的な要素がある場合でも、複数回の実行から同等の統計的結論を得られる。

すべての実験がR2を満たす必要はない。ただし、各実験がどの段階まで満たしているかは明記する。

## 7. 外部資産

外部資産は、原則としてリポジトリへ直接取り込まない。

主な対象:

- MaleCNS
- FlyBody
- FlyGym / NeuroMechFly
- MuJoCo

必要な場合は、取得スクリプトと使用版を固定する。

## 8. 大容量ファイル

次のようなファイルはGitで管理しない。

- コネクトームの生データ一式
- EM画像の大容量データ
- 大型メッシュ
- チェックポイント
- 軌跡データ
- 描画済み動画
- 詳細な性能計測記録

代わりに、再取得・再生成に必要な来歴記録、設定、ハッシュ値、要約レポートをGitで管理する。

## 9. Hugging Faceでのチェックポイント配布

第三者向けのチェックポイント本体はGitHubのソースリポジトリとは分けて配布する。Hugging Faceの`shute2004/virtual-fly`には概要ページを準備済みだが、以下の4つのチェックポイント用リポジトリはまだ作成・公開していない。

公開時は次の4系統を明確に分離する。

- canonical v1の初期チェックポイント: `virtual-fly-initial-YYYYMMDD`
- canonical v1の学習後チェックポイント: `virtual-fly-trained-YYYYMMDD`
- 公開動画Before側の過去チェックポイント: `virtual-fly-video-before`
- 公開動画After側の過去チェックポイント: `virtual-fly-video-after`

`YYYYMMDD`は実際の公開日にのみ確定する。動画用の過去チェックポイントは、同じ実行系から読み込める場合でもcanonical v1の初期・学習後チェックポイントとして扱わない。

公開時、各チェックポイントリポジトリには、ネイティブ形式のチェックポイント一式と、`README.md`、帰属情報、来歴記録、SHA-256一覧だけを置く。モデル利用や検証に直接必要でない全軌跡、フレーム群、生データ、無関係なチェックポイント、ビルド生成物は含めない。

チェックポイントの重みはMaleCNS `male-cns:v1.0`に由来し、公式配布元ではCC BY 4.0で公開されている。MaleCNSの生データ自体はHugging Faceへ複製せず、公式配布元またはcanonicalの取得・再現経路から取得する。FlyBody / FlyGym / MuJoCoの資産も、利便性だけを理由にチェックポイントリポジトリへ複製しない。

準備済みのモデルカード、正確なチェックポイントハッシュ、必要ファイル一覧は [`../../release/huggingface/`](../../release/huggingface/README.md) に記録する。

## 10. 過去資料に残るローカルパス

一部の過去の開発記録や履歴レポートには、実行・例外記録・レポート生成を行った当時の絶対ローカルパスが残っている。これらは後から書き換えず、元の来歴記録の一部として保持する。現行コードの依存先や導入要件ではなく、現在の公開文書と実行コマンドはリポジトリ相対または移植可能なパスを使用する。

## 11. 公開ブラウザ実験

ブラウザから返ってくる結果は、信頼できる内部状態とは分けて扱う。

各結果には最低限、次の情報を含める。

- 実験パッケージの版
- 初期状態のハッシュ値
- 設定のハッシュ値
- 実行方式
- 結果のハッシュ値
- 要約指標

重要な結果は、サーバー側または複数の独立した実行環境で再実行して確認する。

## 12. 個人データ

公開実験では、神経科学上不要な個人情報やブラウザ識別情報を収集しない。

計算参加に必要な実行環境情報を取得する場合も、その目的と保持範囲を明示する。
