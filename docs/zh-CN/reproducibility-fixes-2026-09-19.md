# 可重现性与规则契约修复 — 2026-09-19

[English](../en/reproducibility-fixes-2026-09-19.md) · [日本語](../ja/reproducibility-fixes-2026-09-19.md) · [简体中文](reproducibility-fixes-2026-09-19.md)

这组修改用于修复研究开源发布前审计中发现的、会影响今后可重现性和规则契约的问题。它**不会**改写历史检查点，也不会把旧成果重新解释成由当前规则生成。

## 不改变的科学含义

本次修改不改变：

- MaleCNS 拓扑结构和公开连接数；
- 神经活动动力学及由神经递质决定的快速符号假设；
- 局部三因素可塑性公式、学习率、资格度动力学和权重提交公式；
- 通过门洞时的 PAM 刺激和碰撞时的 PPL 刺激；
- 单个运动神经元边界及外周运动映射；
- 视网膜感觉转换规则；
- 平衡器物理感觉转换方程；
- 共享权重的加法、截断和重新应用规则。

本次只修改验证、来源记录、配置传递、报告和检查点契约。

## 1. MaleCNS class-DAN 快照契约

**问题：** 当前代码可能静默加载 class-DAN 引入前的 MaleCNS 快照。缺少 `modulator_roles_file` 时会退回 `consensus neurotransmitter == dopamine`，从而恢复旧的 392 来源定义。

**修复：** 当前使用的 MaleCNS 快照必须声明 `runtime_semantics=male-cns-v1-class-dan-v1`、准确的 class-DAN 定义、神经调制角色文件、源文件哈希、生成文件哈希以及生成时的 Git 来源。Rust 和 Python 的当前执行入口在缺少这一契约时直接拒绝运行。只有显式设置 `VF_ALLOW_LEGACY_MALECNS_SNAPSHOT=1` 时，Rust 快照边界才允许历史重放。

**科学影响：** 已采用的 class-DAN 规则本身没有改变，只是防止意外退回旧规则。

**验证：** Python 可重现性测试覆盖旧规则拒绝与正确 class-DAN 快照接受；`vf-neural` 测试覆盖正常快照与运行行为。

## 2. 平衡器完整映射与时间输入子集的区分

**问题：** `haltere-campaniform-sensory-v1`（195 个候选）与 `haltere-timing-afferents-v1`（推断的 97 个时间输入神经元）JSON 结构兼容，时间映射缺失时可能被完整映射生成器错误生成并使用。

**修复：** 两类成果物现在具有不同的 `kind` 值以及生成器和源数据来源记录。启动器、输入准备、子进程和运行时传感器都会检查要求的类别与数量。时间输入映射必须由已验证的完整映射生成，并绑定到当前 MaleCNS 快照来源。

**科学影响：** 195 细胞和 97 细胞定义本身不变，只防止二者互相替代。

## 3. FlyBody v7/v8 neutral trim 的可重现性

**问题：** 身体版本 v7/v8 需要 `wing-pattern-neutral-trim-v1.npy`，但全新检出时并不能可靠生成；已有配平文件也缺乏足够来源信息，无法区分当前生成物与历史本地文件。

**修复：** 当前两个 trim 文件都不存在时，生产启动器会生成它们，并验证元数据规则、模式哈希和生成时来源。v7 身体适配层在使用前也会验证。历史 trim 重放必须显式设置 `VF_ALLOW_LEGACY_FLYBODY_ARTIFACTS=1`。

**科学影响：** 中立配平系数和 v7 谱系（`v4 + neutral trim`）不变。

## 4. 每次运行的来源记录

**问题：** 过去的实验摘要无法充分还原某次运行实际使用的代码和派生产物。

**修复：** 新的多实例运行会写入每次运行的来源 JSON，并把同样信息嵌入摘要。至少记录：

- Git SHA、dirty 状态及其哈希；
- `uv.lock` / `Cargo.lock` 哈希；
- MaleCNS 快照规则身份与哈希；
- 使用的派生映射与校准产物哈希；
- 神经运行、可塑性、DAN/快照、检查点和神经步数规则；
- 身体/环境版本及关键身体参数；
- 视觉方式、射线数量、光感受器增益；
- 平衡器类别、增益和转换方式；
- 奖赏/厌恶刺激电流、持续时间及门洞失误分级参数；
- 随机种子与固定路线种子；
- 多实例启动、经历条件调度和权重提交条件。

子进程执行方式会在工作进程报告实际解析结果后，把真实运行方式和视觉条件补写到记录中。

**科学影响：** 仅增加元数据。

## 5. 派生成果物来源

**问题：** 影响运行结果的派生成果物过去可能仅因为路径存在就被复用，即使它们由不同代码或不同快照生成。

**修复：** 当前生成器会记录生成时 Git 来源和源快照哈希。生产输入准备会验证身体神经群、视网膜映射、翼/身体运动神经元映射、平衡器映射、可视化图、神经校准、neutral trim 等成果物。过期文件会直接拒绝使用，而不会静默成为当前成果物。

**科学影响：** 验证层不会改变生成物的科学内容。

## 6. 多实例检查点契约

**问题：** 多实例检查点使用完整 `NeuralState` 文件布局，但恢复时实际上只恢复共享权重。`checkpoint_neural_step` 也容易被误解为单个个体经过的神经时间，而实际表示所有槽位神经步数总和。

**修复：** 新检查点清单显式声明：

- `checkpoint_semantics=global-weights-only-v1`；
- `step_semantics=aggregate-slot-neural-step-count-v1`。

多实例状态和摘要会重复这一契约，并说明恢复时短期状态会重置。除非显式允许历史重放，否则 Python 和 Rust 都拒绝没有该契约的检查点。历史重放只能通过 `VF_ALLOW_LEGACY_POPULATION_CHECKPOINT=1` 开启。

**科学影响：** 恢复时只继承权重的行为没有改变，只是从隐式行为变成了明确、默认拒绝不兼容输入的契约。

## 7. 身体、环境与感觉条件的兼容性可见性

**问题：** 身体版本和环境版本是独立维度，但历史上可以启动跨代组合而没有足够明显的来源记录。

**修复：** 分别记录身体版本、环境版本和感觉条件。混合不同世代的组合会发出兼容性警告，但不会禁止，因为历史开发过程确实有意使用过混合条件。

## 8. 子进程配置传递

**问题：** 子进程方式会静默丢弃父进程传入的非默认 `neutral_trim_strength`、`steering_tau_ms` 和 `steering_spike_increment`。

**修复：** 这些字段以及快照和平衡器类别身份现在都会准确传入子工作进程。

**科学影响：** 默认运行不变；非默认实验现在会按请求值执行。

## 9. gate2-height 报告含义

**问题：** `latest.md` 可能使用遗留的 adaptive / boundary-band 描述和状态来解释 gate2-height 运行。

**修复：** 报告根据 `curriculum_mode` 分支，gate2-height 使用自己的判定和状态区块，不再把其他经历调度方式写成当前行为。

**科学影响：** 只影响报告。

## 10. 运行历史格式

**问题：** `history.csv` 缺少身体版本、平衡器条件、神经/快照规则、代码身份、依赖身份和检查点规则，因此不同实验可能被压缩到区分度不足的键中。

**修复：** 新历史行加入这些字段，并把主要规则和版本维度纳入运行键。历史行中原摘要不存在的信息保持为空，不通过推断回填。

**科学影响：** 只影响报告和来源记录。

## 11. 公开展示视频的默认条件与来源

**问题：** 通用捕获脚本曾默认使用不自然的 `body=v3`、`environment=v7`、`haltere=0` 组合，容易在不知情的情况下生成与发布展示不一致的结果。

**修复：** 身体版本和环境版本现在必须显式指定。捕获过程也会验证快照和平衡器规则身份，并记录代码、依赖、视觉、身体/环境、平衡器和神经运行规则来源。

**科学影响：** 已有发布展示启动器本来就显式使用 v7/v7/时间输入平衡器，因此其预期行为不变。

## 历史结果不会被重写

本修复不会修改或重新标记审计中已经确认的历史事实，包括：提交前的 v240/v960 来源、v960 以前使用的旧多巴胺来源定义、混合的 v966 谱系、v240 已经经历 240 个训练阶段、v240/v966 评估并非 hold-out、评估期间仍有 PAM 刺激、PPL 刺激强度随任务误差变化、历史 v3 谱系混合、异步与串行算法差异，以及真实的 v7 继承关系。
