# 需求定义

[English](../en/requirements.md) · [日本語](../ja/requirements.md) · [简体中文](requirements.md)

## 1. 目标

`virtual-fly` 的目标是：以成年雄性果蝇的中枢神经系统连接组作为初始状态，在计算机中持续演化神经活动与可塑性，并把神经系统与虚拟身体、感觉器官和环境连接成闭环。

第一个验证任务采用类似 Flappy Bird 的环境。实验关注的是：虚拟果蝇通过感觉输入和与成功、失败对应的神经调制刺激，在没有外部学习算法直接优化神经系统的情况下，行为能否发生变化。

## 2. 非目标

初始阶段不以以下内容为目标：

- 在连接组上叠加传统人工神经网络或 Transformer；
- 用反向传播、梯度下降、Q 学习、策略梯度等方法直接优化神经系统；
- 单纯制作一个追求高分的游戏人工智能；
- 一开始就声称已经完整重现真实果蝇；
- 重现从胚胎到成虫的神经发育过程。

## 3. 基本概念

### 3.1 连接组是初始条件

MaleCNS `v1.0` 等实测连接组被视为 `t = 0` 时刻的神经系统状态。

连接关系并不被假定为永久固定。随着模拟经历推进，突触强度、功能有效性以及未来的结构状态都可以变化。

### 3.2 学习发生在神经系统内部

外部程序不直接指定突触更新量。

原则上，外部只提供两类输入：

1. 把外界和身体状态转换成感觉神经活动后的刺激；
2. 把成功、失败等事件表示为对生物学上相关神经回路的神经调制刺激。

神经系统通过由此产生的局部神经活动和可塑性而发生变化。

### 3.3 行为由神经系统产生

环境侧不能作出 `move_up()`、`turn_left()` 之类的动作决策。

神经活动进入运动通路，再映射到肌肉、关节、翅等身体状态，由身体运动进一步改变环境。

## 4. 功能需求

### FR-01：导入 MaleCNS 数据

系统应能够：

- 导入成年雄性果蝇全中枢神经系统连接组的指定版本；
- 以 `male-cns:v1.0` 作为最初基准数据；
- 保留神经元 ID、细胞类型、可用的形态信息、突触连接、连接数、神经递质信息和注释；
- 记录数据集版本、获取时间和转换过程。

### FR-02：神经状态随时间演化

- 每个神经元都具有随时间变化的内部状态；
- 能根据外部刺激和突触输入推进到下一时刻；
- 不把神经计算视为固定图上的单次前向传播，而是连续或离散时间动力系统；
- 神经模型可以替换。

### FR-03：动态突触

每个突触或聚合连接至少应能表示以下可变状态：

- 有效强度；
- 可塑性状态；
- 激活或失活状态；
- 将来用于形成和消失连接的状态。

初始实现不要求同时启用所有机制，但架构不能只能表示永久固定的连接。

### FR-04：神经调制

系统应支持：

- 对奖赏相关多巴胺能回路进行刺激；
- 对厌恶学习相关回路进行刺激；
- 不把 `reward` 之类抽象标量作为神经系统内部的直接学习输入；
- 把刺激对象、强度和时间模式保存为实验条件。

### FR-05：感觉转换

首先优先实现视觉。

系统应能够：

- 从三维环境生成进入虚拟复眼的视觉信息；
- 把这些信息转换成送入 MaleCNS 视觉入口的神经刺激；
- 对 MaleCNS 中不存在的感觉器官或外周结构，使用与 CNS 模型清晰分离的补充模型。

将来可扩展嗅觉、机械感觉和本体感觉。

### FR-06：身体连接

- 优先考虑使用 FlyBody / FlyGym / MuJoCo 作为身体与物理基础；
- 提供把 CNS 运动输出映射到身体执行机构的层；
- 这一映射层不得包含行为决策，只表示生物学上的对应关系；
- 将来可以替换为更详细的肌肉模型。

### FR-07：闭环环境

系统必须能够持续循环：

1. 环境状态；
2. 感觉转换；
3. 神经活动；
4. 运动输出；
5. 身体物理；
6. 更新后的环境状态。

### FR-08：Flyppy 实验

系统应能够：

- 生成带障碍物的飞行环境；
- 仅根据虚拟果蝇的身体运动更新其位置；
- 把成功、碰撞等事件转换为神经刺激；
- 比较经历前后的行为；
- 固定环境条件和刺激条件后重新执行实验。

### FR-09：状态保存

在某个时间点，虚拟果蝇至少应能保存并恢复：

- 数据集与模型版本；
- 神经元状态；
- 突触状态；
- 可塑性状态；
- 神经调制状态；
- 身体状态；
- 实验时间；
- 随机数生成器状态。

实际运行中的检查点格式可以有意只持久化其中一部分，但这种含义必须明确写出。

### FR-10：实验记录

每次实验记录：

- 初始个体 ID；
- 派生个体 ID；
- 代码提交 SHA；
- 输入数据版本；
- 神经模型版本；
- 可塑性模型版本；
- 身体模型版本；
- 环境配置；
- 刺激历史；
- 主要神经活动统计；
- 行为结果。

### FR-11：多个体实验

可以复制同一初始 CNS 状态，并在不同经历、随机种子或刺激条件下分支成多个个体。

### FR-12：未来的浏览器分布式执行

架构应为以下能力保留空间：

- 在 WebAssembly / WebGPU 上运行；
- 在参与者电脑上执行独立实验个体；
- 把实验结果发送到中央服务；
- 对贡献计算资源进行明确同意；
- 只观看而不参与计算的模式；
- 面对重复、篡改或异常客户端结果时进行验证。

## 5. 非功能需求

### NFR-01：科学来源

每个值都应能够归类为：

- `observed`：实测数据；
- `literature`：文献来源；
- `inferred`：根据实测信息推断；
- `assumed`：实现中的假设；
- `calibrated`：根据数值或实验校准。

假设不得写成实测事实。

### NFR-02：可重现性

在版本、初始状态和随机数序列相同时，除规定的数值误差外，应能够重现实验。

### NFR-03：模块化

以下部分应能够独立替换：

- 神经动力学；
- 可塑性；
- 神经调制；
- 感觉转换；
- 神经到身体的映射；
- 身体模型；
- 环境；
- 保存格式。

### NFR-04：性能

- 先在小型子回路上验证正确性；
- 全中枢神经系统使用稀疏表示，避免为每个神经元和突触创建大量 Python 对象；
- CPU 参考实现与未来 GPU / WebGPU 加速保持可分离。

### NFR-05：可观测性

模拟过程中，应能跟踪指定神经元或神经元群的状态、放电、突触变化和神经调制。

### NFR-06：外部资源分离

MaleCNS、FlyBody、FlyGym、MuJoCo 等不会无条件重新分发；应遵守各自许可和使用条件，并管理获取脚本、转换过程、哈希值和引用信息。

## 6. 初始成功条件

第一个里程碑不以“成功玩好 Flappy Bird”为成功标准。

最低成功条件是：

1. MaleCNS 的部分或全部可以转换成可重现的内部表示；
2. 神经活动能够随时间演化；
3. 突触状态能够随神经活动和神经调制改变；
4. 与虚拟身体形成双向闭环；
5. 在相同条件下能够比较开启和关闭可塑性时的行为差异；
6. 如果出现持续的行为变化，能够把它与神经状态和突触状态的变化对应起来。

## 7. 待确定事项

以下内容需要在实现前或每次实验中明确：

- 首先采用的神经动力学模型；
- 初始突触强度如何从连接数推导；
- 在什么阶段引入兴奋性、抑制性和神经递质信息；
- 初始可塑性规则；
- 何时引入结构可塑性；
- 如何补充视觉外周系统；
- CNS 运动输出到 FlyBody 的第一版映射；
- 奖赏与厌恶刺激具体使用哪些细胞群和刺激模式。
