# 開発ロードマップ

## 方針

大規模な全CNS・3D身体・Web分散実験を一度に作らない。

各段階で「何が動いたら次へ進めるか」を明確にし、科学モデルとソフトウェア基盤を同時に検証する。

## Phase 0: データと外部資産の固定

### 作業

- MaleCNS `male-cns:v1.0` の取得方法を実装する。
- neuPrint APIと一括データのどちらを基準入力にするか決める。
- ニューロン・シナプス・注釈の内部スキーマを定義する。
- FlyBody / FlyGym / MuJoCo の利用バージョンを固定する。
- 外部資産のライセンス・引用・ハッシュを記録する。
- MaleCNSに含まれる／含まれない感覚・末梢構造を一覧化する。

### Exit criteria

- 同じ入力版から同じ内部connectome snapshotを再生成できる。
- データ来歴を機械可読manifestで残せる。

## Phase 1: 神経系最小ランタイム

### 作業

- Rust workspaceを作る。
- ニューロン状態配列を実装する。
- 疎な接続ストアを実装する。
- 小規模サブグラフで時間発展を実装する。
- 外部刺激の注入を実装する。
- Python bindingを作る。
- 決定論テストを用意する。

### Exit criteria

- 小規模神経回路へ刺激を与え、活動伝播を追跡できる。
- 同じseedと状態から同じ結果を再現できる。

## Phase 2: 機能可塑性と神経修飾

### 作業

- 可塑性インターフェースを実装する。
- 最初の文献ベース可塑性則を実装する。
- 神経修飾状態を実装する。
- 報酬・嫌悪回路への刺激イベントを実装する。
- シナプス強度変化を保存・可視化する。
- 可塑性OFF対照を同じランタイムで実行可能にする。

### Exit criteria

- 同一入力に対する応答が経験後に持続的に変化する実験を構成できる。
- 変化したシナプスを追跡できる。

## Phase 3: 全CNSスケール

### 作業

- MaleCNS全体をロードする。
- メモリ使用量とstep性能を測定する。
- 疎接続表現・イベント処理を最適化する。
- 活動の暴走・消失を検出する診断を作る。
- CPU参照実装と高速backendの一致を検証する。

### Exit criteria

- 全CNS相当の状態を一定時間、安定してシミュレートできる。
- チェックポイント保存・再開ができる。

## Phase 4: 身体と感覚

### 作業

- FlyBody/FlyGym adapterを実装する。
- 3D環境から複眼入力を生成する。
- 視覚末梢系からMaleCNS入口への変換を実装する。
- CNS運動出力から身体アクチュエータへの初期写像を作る。
- 身体から自己受容・接触情報を返すための境界を作る。

### Exit criteria

- `environment -> sensory -> CNS -> motor -> body -> environment` の閉ループが成立する。
- ゲーム攻略ロジックなしで身体が神経活動に応じて動く。

## Phase 5: 自発活動と既知応答の検証

### 作業

- baseline activity / spontaneous activity条件を調査・実装する。
- 単純な視覚刺激に対する応答を検証する。
- 既知のショウジョウバエ神経・行動データと比較する。
- 神経モデルの不足箇所を特定する。

### Exit criteria

- 外部の行動命令なしで神経系と身体が継続動作する。
- 少なくとも一部の既知刺激応答を定性的または定量的に比較できる。

## Phase 6: Flyppy v0

### 作業

- 最小の障害物環境を作る。
- 成功／失敗イベントを定義する。
- イベントを報酬／嫌悪回路への刺激へ変換する。
- 可塑性あり・なし・非随伴・yoked controlを自動実験する。
- 行動・神経・シナプス指標を記録する。

### Exit criteria

- 多数の同一初期個体を分岐して比較できる。
- 行動変化を神経系変化と対応付けて解析できる。

## Phase 7: 構造可塑性

### 作業

- 形成・消失規則の文献調査を行う。
- structural delta layerを実装する。
- 形成候補探索を局所化し、計算量を制御する。
- 構造変更をcheckpointへ保存する。
- 機能可塑性だけの場合との比較を行う。

### Exit criteria

- 接続形成・消失を含む個体状態を保存・再現できる。
- 構造変更が行動・神経活動へ与える影響を追跡できる。

## Phase 8: 高速化・大量個体

### 作業

- 並列個体実行を実装する。
- GPU backendを評価する。
- 実験結果の列指向保存・集約を整備する。
- 数百〜数千個体規模の実験管理を行う。

### Exit criteria

- 大量個体の比較実験を自動実行できる。
- 同一初期脳から経験による分岐を統計解析できる。

## Phase 9: Web公開

### 作業

- 3D viewerと神経活動可視化を作る。
- WASM版神経ランタイムを作る。
- WebGPU適用範囲を決める。
- 明示的な計算参加UIを作る。
- 実験ジョブ配布と結果送信を実装する。
- クライアント結果の検証・重複排除を実装する。

### Exit criteria

- 一般ユーザーがブラウザで仮想ハエを観察できる。
- 同意したユーザーのPCで実験個体を実行できる。
- 収集結果から再現可能な実験データセットを構築できる。

## Phase 10: 公開実験基盤

最終段階では、公開サイトを単なるデモではなく分散実験基盤として運用する。

候補機能:

- 現在活動中の仮想個体数
- 累計仮想経験時間
- 個体ごとの系譜
- 学習前後の行動比較
- 神経・シナプス変化の可視化
- 実験条件別の集計
- 再現実験の自動割当

## 優先順位

最優先はPhase 0〜2である。

「3Dのハエを見せる」より先に、**神経系が動き、経験で内部状態が変わり、その状態を検証可能な形で保存できること**を成立させる。
