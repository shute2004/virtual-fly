# 要件定義

## 1. 目的

`virtual-fly` は、成体オスのショウジョウバエの中枢神経系コネクトームを初期状態として、計算機上で神経活動と可塑性を継続的に時間発展させ、仮想身体・感覚器・環境と閉ループ接続することを目的とする。

最初の検証課題は Flappy Bird 型環境である。仮想ハエが環境を感覚入力として受け取り、自身の神経活動から行動し、成功・失敗に応じた神経修飾刺激を受けることで、外部の学習アルゴリズムなしに行動が変化するかを検証する。

## 2. 非目的

初期段階では以下を目的としない。

- 人工ニューラルネットワークや Transformer をコネクトーム上に載せること。
- 誤差逆伝播、勾配降下、Q学習、方策勾配などで神経系を直接最適化すること。
- 高得点を取るゲームAIを作ること自体。
- 生物学的に完全なショウジョウバエを最初から再現したと主張すること。
- 発生初期から成体までの神経発生過程を再現すること。

## 3. 基本概念

### 3.1 コネクトームは初期条件

MaleCNS `v1.0` 等の実測コネクトームを `t = 0` の神経系状態として扱う。

接続関係を永久固定するものとはみなさず、学習中にシナプス強度・有効性・存在状態などが変化できる構造とする。

### 3.2 学習は脳内部で起こす

外部プログラムはシナプス更新量を指定しない。

外部から与えるのは原則として次の二種類である。

1. 外界・身体状態を感覚神経活動に変換した刺激。
2. 成功・失敗などを、生体で報酬・嫌悪に関与する神経回路への刺激として表現した神経修飾入力。

その結果として生じる局所的な神経活動と可塑性によって神経系が変化する。

### 3.3 行動は脳から発生させる

環境側は `move_up()` や `turn_left()` のような意思決定を行わない。

神経系の活動を運動系へ伝え、筋・関節・翅などの身体状態へ変換し、その身体運動が環境を変化させる。

## 4. 機能要件

### FR-01: MaleCNS データ取り込み

- 成体オス全CNSコネクトームの特定バージョンを取り込めること。
- 最初の基準データは `male-cns:v1.0` を候補とする。
- ニューロンID、細胞型、形態情報、シナプス接続、接続数、利用可能な神経伝達物質・注釈等を保持できること。
- データセットのバージョン・取得日時・変換手順を記録すること。

### FR-02: 神経状態の時間発展

- 各ニューロンが時間依存の内部状態を持てること。
- 外部刺激・シナプス入力から次時刻の状態を計算できること。
- 神経活動を固定グラフの一回の順伝播として扱わず、連続的または離散時間の動的系として扱うこと。
- 神経モデルは交換可能にすること。

### FR-03: 動的シナプス

最低限、各シナプスまたは接続集約単位について以下を変更可能にする。

- 有効強度
- 可塑性状態
- 活性・非活性
- 形成・消失に必要な状態

初期実装では全要素を同時に有効化する必要はないが、固定接続しか表現できない設計にはしない。

### FR-04: 神経修飾

- 報酬に関連するドーパミン作動性回路へ刺激を注入できること。
- 嫌悪学習に関連する回路へ刺激を注入できること。
- 単一の抽象的な報酬値（例: `reward`）を、神経系内部の学習用入力として使用しないこと。
- 刺激対象、強度、時間パターンを実験条件として保存すること。

### FR-05: 感覚変換

最初は視覚を優先する。

- 3D環境から仮想複眼に入る視覚情報を生成すること。
- 視覚情報を、MaleCNS 内の視覚系入口へ与える神経刺激へ変換すること。
- MaleCNS 自体に含まれない感覚器・末梢部分がある場合、その補完モデルをCNSモデルから明確に分離すること。

将来は嗅覚、機械感覚、自己受容感覚等を追加可能にする。

### FR-06: 身体との接続

- FlyBody / FlyGym / MuJoCo を第一候補として仮想身体を利用できること。
- CNS の運動出力を身体アクチュエータへ変換する層を持つこと。
- この変換層は意思決定を行わず、生物学的対応関係の写像に限定すること。
- 将来、より詳細な筋モデルへ差し替え可能にすること。

### FR-07: 閉ループ環境

1. 環境状態
2. 感覚変換
3. 神経活動
4. 運動出力
5. 身体物理
6. 新しい環境状態

を連続的に循環させられること。

### FR-08: Flyppy 実験

- 障害物を含む飛行環境を生成すること。
- 仮想ハエの身体運動だけで環境内の位置を更新すること。
- 成功・衝突等のイベントを神経刺激へ変換できること。
- 学習前後の行動変化を比較できること。
- 環境条件と刺激条件を固定して再実行できること。

### FR-09: 状態保存

ある時点の仮想ハエについて、少なくとも以下を保存・再開できること。

- データセットとモデルのバージョン
- ニューロン状態
- シナプス状態
- 可塑性状態
- 神経修飾状態
- 身体状態
- 実験時刻
- 乱数生成器の状態

### FR-10: 実験記録

実験ごとに次を記録する。

- 初期個体ID
- 派生個体ID
- コードのコミットSHA
- 入力データ版
- 神経モデル版
- 可塑性モデル版
- 身体モデル版
- 環境設定
- 刺激履歴
- 主要な神経活動統計
- 行動結果

### FR-11: 多個体実験

同一の初期CNS状態をコピーし、異なる経験・乱数・刺激条件で複数個体へ分岐させられること。

### FR-12: 将来のブラウザ分散実行

将来的に以下を可能にする設計余地を持つ。

- WebAssembly / WebGPU 上での仮想ハエ実行。
- 閲覧者PCで独立した実験個体を実行。
- 実験結果を中央サーバへ返送。
- ブラウザ計算への明示的な参加同意。
- 見学のみのモード。
- 改ざん・重複・異常データを前提とした検証。

## 5. 非機能要件

### NFR-01: 科学的来歴

各値を以下に分類できること。

- `observed`: 実測データ
- `literature`: 文献由来
- `inferred`: 実測値から推定
- `assumed`: 実装上の仮定
- `calibrated`: 実験に合わせて較正

仮定を実測値として扱わない。

### NFR-02: 再現性

同一バージョン・同一初期状態・同一乱数系列で、数値誤差の範囲を除き同一実験を再現できること。

### NFR-03: モジュール性

以下を独立して交換可能にする。

- 神経ダイナミクス
- 可塑性
- 神経修飾
- 感覚変換
- 神経→身体写像
- 身体モデル
- 環境
- 保存形式

### NFR-04: 性能

- まず小規模サブ回路で正しさを検証できること。
- 全CNSは疎な接続構造として扱い、ニューロン・シナプスごとのPythonオブジェクト大量生成を避けること。
- CPU上の参照実装と、将来のGPU/WebGPU高速化を分離可能にすること。

### NFR-05: 観測可能性

シミュレーション中に、個別ニューロンまたは指定集団について状態・発火・シナプス変化・神経修飾を追跡できること。

### NFR-06: 外部資産の分離

MaleCNS、FlyBody、FlyGym、MuJoCo等は本リポジトリへ無条件に再配布せず、各ライセンス・利用条件に従う。取得スクリプト・変換スクリプト・ハッシュ・出典を管理する。

## 6. 初期成功条件

最初のマイルストーンでは「Flappy Birdを上手く解ける」こと自体を成功条件にしない。

最低成功条件は以下とする。

1. MaleCNS の一部または全体を再現可能な内部形式へ変換できる。
2. 神経活動が時間発展する。
3. シナプス状態が活動・神経修飾によって変化する。
4. 仮想身体との双方向閉ループが成立する。
5. 同一条件で、可塑性あり・なしの行動差を測定できる。
6. 学習に相当する持続的な行動変化が出た場合、その変化を神経状態・シナプス状態の変化と対応付けて追跡できる。

## 7. 保留事項

実装前または実験ごとに確定する。

- 最初に採用する神経ダイナミクスモデル。
- 初期シナプス強度を接続数からどう導出するか。
- 興奮性・抑制性・神経伝達物質情報をどの段階から導入するか。
- 最初の可塑性則。
- 構造可塑性を導入するタイミング。
- 視覚末梢系の補完方法。
- CNS運動出力からFlyBodyへの最初の写像。
- 報酬・嫌悪刺激に使用する具体的な細胞群と刺激パターン。
