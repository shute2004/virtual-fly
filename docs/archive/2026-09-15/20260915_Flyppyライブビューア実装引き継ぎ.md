# Flyppy ライブビューア実装 引き継ぎ

対象ブランチ: `feat/flybody-flyppy-loop`

この文書は、Flyppy v3 の detached live viewer 周りの実装・不具合修正・実測確認が一区切りついた時点の状態を、次のコンテクストへ引き継ぐためのものです。

## 1. 現在の結論

ライブビューアは実ブラウザで動作確認済みです。

確認済み:

- training は viewer 無しで headless のまま開始できる
- training 途中から別ターミナルで viewer を起動できる
- FlyBody の MuJoCo 映像が実際に動く
- MaleCNS 小窓の neuron firing 表示が動く
- synapse 表示・発火残光・pre→post 伝播パルスが動く
- `VF_POPULATION_TELEMETRY=1` は通常 viewer 利用には不要
- viewer 未接続中は `body.json` / `neural.json` を生成しない
- viewer 接続中だけ body snapshot / viewer neural read / telemetry JSON を生成する
- viewer 切断後も training は継続する
- viewer 切断後は `body.json` / `neural.json` の更新が止まる

## 2. 実運用

training は通常どおり起動する。

```bash
bash scripts/dev/train_flyppy_v3_population.sh
```

見たくなった時だけ別ターミナルで:

```bash
bash scripts/dev/view_flyppy_v3.sh
```

ユーザーの実際の運用では:

- ターミナル1 = training
- ターミナル2 = viewer

viewer を閉じても training はそのまま継続する。

## 3. 主要root causeと修正

実ブラウザでviewerが開くのに映像もMaleCNSも動かなかった主原因は、viewer/trainer rendezvous 用 Unix socket identity が experiment path の文字列表記に依存していたこと。

macOS の case-insensitive filesystem では:

```text
/Users/.../Desktop/virtual-fly
/Users/.../desktop/virtual-fly
```

は同じ物理ディレクトリを指すが、旧実装は文字列をSHA-256していたため別socketになっていた。

修正後は filesystem identity (`st_dev`, `st_ino`) を用いて socket token を生成する。

対象:

- `scripts/embodiment/live_telemetry.py`
- `scripts/embodiment/live_viewer_server.py`

これにより case alias / symlink alias を同一物理directoryとして扱う。

viewer 側は接続失敗時に socket path を再計算するため、experiment directory が再作成され inode が変わっても追従できる。

独立原因分析:

- `docs/archive/2026-09-15/20260915_2040_Flyppyライブビューア不具合原因分析.md`

修正結果:

- `docs/archive/2026-09-15/20260915_2055_Flyppyライブビューア不具合修正結果.md`

## 4. viewer architecture

```text
production Flyppy trainer
  ├─ viewer無し
  │    ├─ body viewer snapshot無し
  │    ├─ viewer neural read無し
  │    └─ body/neural telemetry JSON無し
  │
  └─ viewer接続中
       ├─ Unix stream lease
       ├─ body snapshot
       ├─ viewer neural body-ID read
       ├─ live/body.json
       ├─ live/neural.json
       └─ live/status.json
              │
              ├─ detached live_body_viewer.py
              │      └─ live/fly.png
              │
              └─ browser live-neural-viewer.html
```

training process は renderer / browser / viewer camera state を所有しない。

## 5. socket demand polling

viewer未接続時の `publisher.requested()` は毎control loopでkernel syscallを打たないよう、短時間cacheを入れている。

現在の未接続pollは最大約20回/秒。

viewer attach/detach 反応遅延は最大およそ50ms。

## 6. FlyBody viewer

`scripts/embodiment/live_body_viewer.py`

- training とは別の MuJoCo model/data を持つ
- `body.json` の `qpos/qvel` を observer model に適用
- training physics をstepしない
- `mj_forward` + renderer で `fly.png` を生成
- camera操作は `live/camera.json` を通す
- stale `body.json` が消えた場合は古いposeを保持し続けない
- v3 viewer は v3 environment を明示

launcher:

- `scripts/dev/view_flyppy_v3.sh`
- `scripts/dev/view_flyppy.sh`

HTTP server と body renderer の両方を監視し、rendererが死んだ場合にページだけ生き残る状態を避けている。

## 7. MaleCNS viewer

`visualization/live-neural-viewer.html`

静的graph:

- `artifacts/embodiment/neural-viewer-graph-v1.json`
- 最大約2,500 nodes / 6,000 edges
- released MaleCNS body ID と released connection を使用
- node位置は現時点では模式配置
- 実 morphology / synapse 3D座標ではない

現在の表示:

- neuron firing
- 発火残光
- synapse強度の基礎明度
- presynaptic firing時のconnection発光
- pre→post方向の伝播パルス
- reward/PAM event 表示
- aversive/PPL1 event 表示

これらは既存の viewer telemetry と静的graphだけを使い、追加の MaleCNS runtime read を増やしていない。

## 10. viewer runtime overhead 実測

`reports/flyppy/viewer_runtime_overhead_v2.md`

constant population=4 / direct-ray K=13 条件:

```text
headless before attach: 27.862 control steps/s
viewer attached:        26.265 control steps/s
attached/headless:       0.943x
headless after detach:  29.927 control steps/s
after/before:            1.074x
```

つまり、このrunではviewer接続によるproduction training throughput低下は約5.7%。

browser/Three.js rendering自体はこのbenchmarkに含まないが、detached MuJoCo renderer 960x540 @30Hz、trainer-side viewer read/snapshot、Unix stream leaseは含む。

v2 report中の `body_json_stopped_after_detach` / `neural_json_stopped_after_detach` FAIL はbenchmark判定時刻の問題で、実装不具合ではない。切断直後の最後の正当なwriteまで比較対象にしていた。

## 11. detach quiescence 最終確認

`reports/flyppy/viewer_detach_quiescence.md`

診断:

```text
VIEWER_DETACH_QUIESCENCE_OK
```

全check PASS:

- headless_no_body_json
- headless_no_neural_json
- lease_connected
- telemetry_materialized
- body_advanced_while_attached
- neural_advanced_while_attached
- training_advanced_after_detach
- body_quiescent_after_settle
- neural_quiescent_after_settle
- trainer_still_running

観測:

```text
settled_body_mtime_ns == final_body_mtime_ns
settled_neural_mtime_ns == final_neural_mtime_ns

detached_start_records = 136
final_records = 256
```

viewer切断後、trainingがさらに120 trajectory records進んでも body/neural telemetry は更新されなかった。

## 12. 現在のproduction vision

viewerとは別件だが、現在のFlyppy production visionは direct-ray K=13。

```text
3D world
→ physical ommatidial rays
→ receptor signal
→ MaleCNS retinal input
```

デフォルト:

```text
VF_FLYPPY_VISION_MODE=direct-ray
VF_FLYPPY_OMMATIDIA_RAYS=13
```

RGB framebufferはproductionでは不要。

過去のproduction 48 episode runでは:

```text
population=4
packed-process=4
direct-ray K=13
framebuffer=false
32.331 control steps/s
```

## 13. 学習アーキテクチャで維持する不変条件

- scalar rewardを導入しない
- reward = PAM current stimulation
- aversive/collision = PPL1 current stimulation
- individual motor-neuron identityを保持
- generic action decoder NN/RLを追加しない
- generic weight averagingをしない
- async shared-weight transaction rebaseを維持
