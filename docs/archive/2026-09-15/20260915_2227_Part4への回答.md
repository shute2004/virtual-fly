## 1. 現在のFlyppy v3 checkpointを継続学習の正規起点として扱う意図だったか

### 結論

**運用上は、現在の `artifacts/experiments/flyppy-v3/checkpoint` をPart4でもそのまま継続できる「現在の学習個体」として扱う意図でした。**

ただし、これは

> finalizedされた現在のproduction構成だけを使って、初期MaleCNSから学習した実験的に純粋なbaseline

という意味ではありません。

Part3では、v3 physical seamを作り直した段階で `flyppy-v3` を新しい実験系列として開始し、その後は同じv3 checkpointを、runtime最適化・population化・direct-ray cutoverをまたいで継続しました。したがって現在checkpointは、**Part3の開発過程を連続して経験した個体**です。

### 実装上の根拠

`scripts/dev/train_flyppy_v3_population.sh` は通常起動時に `--fresh` を付けません。

また `scripts/embodiment/train_flyppy_population_process.py` は、checkpointが存在すれば明示的に:

- checkpointをload
- curriculum stateをload
- population stateをload
- trajectoryをappend
- 次episode番号から継続

する実装です。

`reports/flyppy/population_resume_probe.md` でも、既存production checkpointをpopulation runtimeへloadする経路を独立に検査してPASSさせています。

### 実際の履歴

`reports/flyppy/history.csv` では、v3系列は次のように連続しています。

```text
v3 source-equivalent / whole-body
  episode 0..71

async shared-weight population
  episode 72..95

direct-ray K=13 production
  episode 96..143
  episode 144..151
  episode 152..159
```

つまり、Part3はruntimeやsensory seamを変更するたびに初期MaleCNSへ戻す運用をしていません。

特にdirect-ray cutover benchmarkはproduction checkpointを変更せずにA/Bを行い、その後、既存のproduction experimentをepisode 96からdirect-ray K=13でそのまま継続しています。

### raster時代など異なる条件の可塑変化を混在させることについて

**Part3では、開発中の継続個体については意図的に許容していました。**

ただし変更の種類は区別する必要があります。

- neural runtime / eager-live plasticity / shared-weight transaction rebase等は、学習意味論を維持することを前提にparity/verificationを行って切り替えたものです。
- direct-ray cutoverは、rasterとsensory semanticsが同一ではないことを明示した上で切り替えています。

したがって、現在checkpointには少なくとも **direct-ray cutover前のv3 sensory historyと、cutover後のdirect-ray historyが同居しています**。

これはPart3の「継続学習個体」としては問題扱いしていませんでしたが、最終構成だけの効果を分離した実験baselineではありません。

### Part4でどう扱うべきか

目的を分けてください。

#### A. Part3からの個体をそのまま育てる場合

現在の `flyppy-v3/checkpoint` を正規のcontinuation checkpointとして使ってよいです。

これはPart3が実際に採用していた運用です。

#### B. finalized production構成そのものの学習能力を評価する場合

現在のcheckpointだけをbaselineにするのは適切ではありません。

この場合は、

```text
v3 source-equivalent physics
+ whole-body motor boundary
+ async shared-weight population
+ eager-live plasticity
+ packed body processes
+ direct-ray K=13
```

を最初から固定し、**初期MaleCNSから別experimentとしてfresh trainingするbaseline**を作る方が実験解釈として明確です。

重要なのは、これは「現在checkpointが壊れているから捨てる」という意味ではありません。

- current checkpoint = Part3から連続する学習個体
- fresh final-config checkpoint = 最終構成の因果解釈用baseline

として別物として保持するのがPart3の状態を最も正確に引き継ぐ扱いです。

## 2. v3 physical seamについて、Part3終了時点で未解決と考えていた物理側の疑いは残っていたか

### 結論

Part3終了時点では、**v3 physical seamの主要な「学習開始を妨げる物理バグ」は閉じた**という扱いでした。

ただし、**固定対称open-loopでのfree-flight attitude stabilityは未解決の既知診断として残っています。**

ここを混同しないでください。

### Part3でblocking条件として閉じたもの

`scripts/dev/train_flyppy_v3_population.sh` は、通常 `scripts/dev/preflight_flyppy_v3.sh` を通してからtrainingを開始します。

このpreflightでblockingになっている主要物理条件は以下です。

#### 1. physical scale / gate clearance

`scripts/embodiment/flybody_v3_physical_spec_smoke.py`

v3のFlyBody physical scaleとFlyppy course geometryを確認します。

#### 2. upstream FlyBodyとのfluid-force vector equivalence

`scripts/embodiment/flybody_v3_upstream_force_vector_ab.py`

official measured wing kinematics、source root pitch `-47.5°` を使い、upstream FlyBodyとv3の3D root fluid force vectorを比較します。

preflightでは診断が

```text
V3_TOTAL_FLUID_VECTOR_APPROXIMATELY_SOURCE_EQUIVALENT
```

でなければtrainingを止めます。

この診断はactive total fluid vectorの誤差が `0.10 body-weight` 以下であることを基準にしています。

したがって、旧構成で疑っていた

- wing frame
- root orientation
- baseline body fluid force
- explicit wing ellipsoid force

の大きなsource-equivalenceずれは、Part3では再調査対象から外してよい状態まで閉じています。

#### 3. production virtual-muscle seamのvertical authority

`scripts/embodiment/flybody_v3_production_muscle_capability.py`

これはrootを診断用に固定して、姿勢不安定と純粋な揚力不足を分離したcapability gateです。

blocking基準は:

```text
source vertical support >= 0.95 BW
production vertical support >= 0.95 BW
production/source support >= 0.90
legacy position actuator除去による差 <= 0.10 BW
tracking degradation <= 0.10
source control cadenceを維持
virtual_power_kd == 0
```

です。

つまりPart3では、**「virtual-muscle seamにそもそも体重を支えるだけのaerodynamic authorityがない」仮説は、trainingを再開する前にblocking probeで棄却する設計**にしています。

### 明示的に残した未解決点: symmetric open-loop attitude stability

`scripts/embodiment/flybody_v3_vertical_flight_capability.py` は、固定された左右対称muscle stateでfree flightを行い、altitude sustain / climbを見る診断です。

しかし `preflight_flyppy_v3.sh` ではこれを意図的に:

```bash
flybody_v3_vertical_flight_capability.py --nonblocking
```

で実行しています。

理由もコード内に明示しています。

upstream FlyBodyのflight task自体がwing-beat generatorの上にclosed-loop policy actionを載せるため、**固定対称open-loopだけで姿勢安定することはsource FlyBodyの要件ではありません。**

したがってPart3の判断は:

```text
open-loop不安定
    != vertical aerodynamic authority不足
    != neural trainingを止める物理バグの証明
```

です。

MaleCNS closed-loop controlがattitude stabilizationを担うことを許容しています。

### 最新runの高度低下をどう解釈していたか

`reports/flyppy/latest.md` ではepisode 152..159について:

```text
spawn高度を一度でも上回ったepisode: 0/8
最大高度gain: -0.006 mm
最大高度loss: 3.349 mm
first gate通過: 2/8
```

となっています。

これは明確な行動上の問題です。

ただしPart3終了時点では、これを直ちに「vertical support physicsが壊れている」とは解釈していませんでした。

理由は、anchored capability gateではvertical authorityを別途確認し、upstream force vector equivalenceもblocking preflightにしているからです。

残っている問いは主に:

- MaleCNSが必要な姿勢安定化を学習・生成できているか
- individual motor-neuron -> virtual muscle torque seamの制御可能性をCNSが実際に利用できているか
- course中の初期速度・gate回避・姿勢変化が高度損失へどう寄与しているか

です。

ここには物理・制御境界の問題が残る可能性はありますが、**「基礎揚力が足りない」「wing frameが間違っている」という旧仮説へ無条件に戻るべき状態ではありません。**

### Part4が物理側で最初に見るべきもの

優先順は以下です。

1. `scripts/dev/preflight_flyppy_v3.sh`
2. `artifacts/embodiment/flybody-v3-upstream-force-vector-ab.json`

まずblocking preflightが現在もPASSすることを前提にし、その上で実flightでの姿勢・torque utilizationを調べる、という順序がPart3の意図です。

## 3. direct-ray K=13をどの段階まで「確定したproduction sensory seam」と見なしていたか

### 結論

**Part3ではdirect-ray K=13をproduction sensory seamとしてcutover済み・確定扱いしていました。**

「rasterとのphotometryやtemporal semanticsが完全一致するまで未確定」という扱いではありませんでした。

### 最も明確な実装上の証拠

`scripts/dev/train_flyppy_v3_population.sh` のproduction defaultは:

```text
VF_FLYPPY_VISION_MODE=direct-ray
VF_FLYPPY_OMMATIDIA_RAYS=13
```

です。

launcherのコメントでも:

- K=13はuncompressed direct receptive-field integralに対して十分収束
- real learning benchmarkでrasterより高速
- rasterはexplicit compatibility/debug oracleとして残す

という位置づけになっています。

つまりarchitecture targetはraster reproductionではなく、**image-free physical ommatidial sensing**です。

### K=13を採用したacceptance evidence

#### 1. uncompressed direct integralへの収束

`reports/flyppy/direct_ommatidia_convergence.md`

referenceはrasterではなく、FlyGym receptive-fieldの全valid source pixelを直接 `mj_multiRay` した95,951 rays/readoutのuncompressed direct integralです。

K=13:

```text
5278 rays/readout
sensor: 13.192 ms
speedup vs full direct integral: 18.017x
light MAE: 0.003953
light Pearson r: 0.999013
MaleCNS current MAE: 0.019294
MaleCNS current Pearson r: 0.990365
```

この結果からK=13をproductionの速度/精度点として選んでいます。

#### 2. real shared-CNS learning loopで成立

`reports/flyppy/direct_vision_cutover_benchmark.md`

population=4、16 episode/caseで:

```text
raster:          20.736 control steps/s
direct-ray K=13: 33.310 control steps/s
ratio:            1.606x
```

さらにdirect側は:

- finite retinal drive
- asynchronous commit成立
- valid checkpoint生成
- framebuffer無し

を満たしています。

このbenchmarkは明示的に:

```text
Behavioral equality to raster is not a cutover requirement.
```

としています。

### rasterとのtemporal/sign差について

差は認識した上でcutoverしています。

`reports/flyppy/direct_ommatidia_temporal_semantics.md` のK=13では:

```text
current Pearson r: 0.915181
current MAE: 0.198368
light-delta Pearson r: 0.853268
```

current magnitude >= 0.1でのsign agreementも約 `69.146%` で、完全一致ではありません。

またphotometry/adaptation probesでもrasterとの差は残っています。

しかし同report自身が:

```text
Raster is a temporal compatibility reference, not biological ground truth.
```

としています。

つまりPart3では、これらを**既知のcompatibility差**として記録し、production cutoverを止める条件にはしていません。

### Part3終了時点で追加の未達acceptance criterionはあったか

**ありません。少なくともPart3では、K=13 cutover後に「この追加指標を満たすまではsensory seam未確定」とする未達gateは残していません。**

実際のproduction launcherもK=13をdefaultにし、48 episode production runとその後のrunをdirect-rayで継続しています。

したがってPart4では、単に

> rasterにもっと近づけられる

という理由だけでsensory seamを再オープンする必要はありません。

### Part4でsensory seamを再オープンするなら

再調査の理由になるのは、rasterとの差そのものではなく、例えば:

- body exclusionが破れてself-hitしている
- eye ray geometry/depthが物理的に誤っている
- K=13がuncompressed direct integralへ再現不能になった
- material/lighting semanticsに明確な物理的不整合が見つかった
- 行動失敗がdirect sensor固有のartifactと因果的に結びついた

といった新しい証拠が出た場合です。

現在のK=13については、Part3としては **production sensory seam確定済み** と引き継いでください。
