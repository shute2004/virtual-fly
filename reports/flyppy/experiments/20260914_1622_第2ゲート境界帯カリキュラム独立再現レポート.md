## 1. 目的

本レポートは、Flyppy第2ゲート学習に導入した `boundary-band` カリキュラムについて、第三者が実験条件・アルゴリズム・観測結果・既知の制約を独立に確認し、同じ手順を再実行できるように記録するものである。

ここで「boundary-bandアルゴリズムが成功した」とは、ハエが課題を十分に学習したという意味ではない。以下の運用上の要件を満たしたことを指す。

1. 既知の難しい端点と易しい端点の間から複数難易度を提示する。
2. 1 episodeごとに難易度を往復させず、batch単位で成績を集計する。
3. batch成功率に応じて、次batchの帯域を `harder / hold / easier` のいずれかへ更新する。
4. episodeごとの難易度、成否、衝突理由、batch後の帯域をGit追跡可能なレポートへ残す。

今回の24 episodeでは、これらの機構が設計どおり動作した。一方、行動学習そのものは未完成である。

## 4. 学習経路

今回の標準経路は以下である。

```text
FlyBody compound eye
→ actual MaleCNS R1-R6 body-ID current
→ whole MaleCNS neural dynamics
→ individual released wing motor-neuron body IDs
→ WingMusclePeriphery
→ FlyBodyMuscleAdapter
→ FlyBody / MuJoCo
→ course event
```

環境側から、action target、Q値、loss、policy gradient、signed scalar rewardは与えていない。

reinforcementはイベント時に実在のDAN groupへ電流を注入する。

- gate通過: `reward_dan` = released MaleCNS `PAM01`
- collision: `aversive_dan` = released MaleCNS `PPL101`
- current: 2.0
- reinforcement duration: 4 neural steps

各通常control stepでは `plasticity=True` でCNSを更新する。

## 6. Boundary-bandアルゴリズム

### 6.1 初期帯域

難しい端点:

```text
hard:
x  = 10.500 mm
z  = 5.290 mm
vx = 350.000 mm/s
```

易しい端点:

```text
easy:
x  = 10.625 mm
z  = 5.3525 mm
vx = 356.250 mm/s
```

実装上、これらは先行する固定条件ドリルで得た成功/失敗境界として扱われている。

### 6.2 5段階の難易度

`hard` と `easy` の間を線形補間し、以下の5水準を使用する。

```text
ease = 0.00
0.25
0.50
0.75
1.00
```

`0.00` が最難、`1.00` が最易である。

24 episode batchでは、水準ごとの提示回数は以下である。

| ease | 回数 |
|---:|---:|
| 0.00 | 4 |
| 0.25 | 5 |
| 0.50 | 6 |
| 0.75 | 5 |
| 1.00 | 4 |

順序はseedとbatch numberから決定論的にshuffleされる。今回のseedは `0` である。

### 6.3 batch更新則

24 episode終了時の成功率を `r` とする。

```text
r >= 0.80        → harder
0.40 <= r < 0.80 → hold
r < 0.40         → easier
```

`harder` の1回の更新量:

```text
x  : target方向へ 0.125 mm
z  : target方向へ 0.0625 mm
vx : target方向へ 6.25 mm/s
```

`easier` の1回の更新量:

```text
x  : 易しい方向へ 0.0625 mm
z  : 易しい方向へ 0.03125 mm
vx : 易しい方向へ 3.125 mm/s
```

低成功率が続いた場合は、初期easy endpointを越えて1帯分まで回復側へ退避できるcapを持つ。

## 10. 行動学習に関する判定

boundary-bandカリキュラムの実装成功と、ハエの学習成功は分けて評価する必要がある。

今回観測できたこと:

- hard端点 `ease=0.00` は0/4成功。
- easy端点 `ease=1.00` でも2/4成功に留まる。
- 中央帯域でも一部成功が出る。
- 成功5回はいずれも第2ゲート通過後にfloor collisionへ至る。
- 第3ゲートへの到達は0回。
- 最終6 episodeは全失敗。

よって、今回の結果から「第2ゲート飛行を安定して学習した」とは判断しない。

また、過去により易しい固定条件で高い成功率を示していた状態から性能が変化している可能性がある。直前にhard条件24連続失敗を経験しており、その間にPPL101刺激を伴うonline plasticityが継続しているためである。ただし、本runだけでは因果関係を確定できない。

## 11. 現在判明している身体側の重要な制約

このrunの解釈には、現在のmotor embodimentの制約を必ず含める必要がある。

### 11.1 能動motor boundaryは羽6自由度のみ

FlyBodyは `ALL_BIOLOGICAL` jointsを持つが、現在の標準motor pathが能動的にトルクを加えるのは左右wingの以下6 DOFのみである。

```text
left:  yaw / roll / pitch
right: yaw / roll / pitch
```

脚、腹部、頭部系、haltere等について、whole MaleCNSからの主要motor outputはまだ標準身体経路へ接続されていない。

したがって、現在の学習結果は「whole CNS + whole body motor embodiment」の性能ではない。CNSが身体側で未接続のmotor outputを生成しても、課題成否へ反映されない可能性がある。

### 11.2 ゲート開口と衝突判定

FlyppyCourseのゲート開口高さは `4.0 mm`（half gap 2.0 mm）である。

解析的course判定では胸部位置を中心とする `body_radius_mm=0.65` の簡略モデルを用いる。一方、MuJoCo側の障害物contact pairは脚・胸部・腹部・頭部を対象とするが、wingは含まれていない。

したがって、viewer上の全身形状、解析的gate判定、MuJoCo contact shapeは完全には一致していない。この点も、今後whole-body motor boundaryと合わせて修正対象とする。

## 12. 結論

今回の24 episodeから得られる結論は次のとおりである。

1. `boundary-band` は、5段階の境界条件をbatch内に混在させる機構として正常に動作した。
2. batch成功率20.8%を正しく集計し、40%未満ルールに従って次帯域を `easier` へ移動した。
3. したがって、旧来の「1成功で即難化・1失敗で即易化」というping-pongを置き換えるカリキュラム機構としては採用可能と判断する。
4. 一方、ハエの行動学習自体は未完成であり、第2ゲート成功は5/24、第3ゲート到達は0である。
5. 現在のmotor embodimentが羽6自由度に限定されているため、以降の大量学習を行う前にwhole-body側のmotor boundary拡張を優先する合理性が高い。
6. 今回の結果は、将来のwhole-body motor boundary導入後に比較する「wing-only motor embodiment」の基準記録として保存する。
